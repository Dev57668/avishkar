Second Read a security-debt scorer for AI-written code

AI assistants write code faster than anyone reviews it. Second Read scans a repository snapshot with deterministic detectors, turns what it finds into a 0–100 security-debt index, and points at the exact lines responsible.

  • 61 documented rules
  • 3 required detectors
  • 390+ automated tests
  • SARIF export
  • GitHub check runs
Open the console How it works

01 What it checks

Python

An AST detector with alias resolution and same-function data flow: SQL built from strings, shell commands, eval, pickle and unsafe YAML, weak hashes, disabled TLS checks, debug mode, path handling.

JavaScript, TypeScript, Java and Go

Token-stream scanners for eval, command and SQL injection, unsanitized HTML sinks, weak hashes and ciphers, unsafe deserialization, unhardened XML parsers and disabled TLS. They are heuristic: no full parser, no cross-file flow.

Secrets and dependencies

AWS keys, GitHub and Slack tokens, private keys and hard-coded passwords; outdated or unpinned packages with known CVEs; wildcard CORS.

02 How it works

  1. 1Uploada .zip of the repo + a name
  2. 2Safe unpackpath traversal, symlinks and zip bombs are rejected
  3. 3Detectorssecrets · code patterns · Python AST, in an isolated process
  4. 4Scoreimpact × exposure × confidence (× age, off by default) → 0–100. Fix effort is tracked separately, never in the score
  5. 5Decidepass / warn / would block, plus SARIF and a GitHub check
D = impact × exposure × confidence × age
index = 100 · (1 − e−ΣD / 20)

Each finding's contribution is listed on the dashboard and the total is recomputed as a reproducibility check. If any detector crashes or times out, the run is marked incomplete, never “clean”.

05 Limitations & what we'd do next

The index is a prioritization signal from provisional, uncalibrated weights. It is not a probability of compromise, a compliance grade, or proof that code is safe.

Is zero findings a pass?

No. Detectors only know the patterns they were written for. An empty result means nothing was detected, not that the code is secure.

How accurate are the detectors?

The calibration corpus is about 80 small labelled cases written by us, split into tuning and held-out sets, with no independent second reviewer. Held-out recall was about 0.8, so real misses exist, and nothing is calibrated or approved.

Which languages are covered?

Python uses an AST detector; JavaScript/TypeScript, Java and Go use heuristic token-stream scanners (no full parser, no cross-file data flow). Other languages, such as Rust, are reported as not evaluated, never as clean.

Can the AI assistant change a result?

No. It is off by default and asks for consent first. You see the exact payload, secrets are redacted, and its explanations can't change severity, state or score.

What would we do with another week?
  • Calibrate the weights on real, labelled repositories.
  • A real JS/TS parser and cross-file taint tracking.
  • Docker sandbox on by default (the only real isolation boundary).
  • Independent second-reviewer labels on real repositories.
