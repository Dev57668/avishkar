01 How it works

  1. Uploada .zip of the repo + a name
  2. Safe unpackpath traversal, symlinks and zip bombs are rejected
  3. Detectorssecrets · code patterns · Python AST, in an isolated process
  4. Scoreimpact × exposure × confidence (× age, off by default) → 0–100 (score-v1). Fix effort is tracked separately, never in the score
  5. Decidepass / warn / would block, plus SARIF and a GitHub check

if any detector crashes or times out, the run is marked incomplete, never “clean”

04 Limitations & what we'd do next

What the score does not tell you

  • Zero findings is not a pass: detectors only know the patterns they were written for.
  • Weights are provisional: the calibration corpus is about 80 small labeled cases written by us, split into tuning and held-out sets, with no independent second reviewer. Held-out recall was about 0.8, so real misses exist, and nothing is calibrated or approved.
  • Python uses an AST detector; JavaScript/TypeScript use a heuristic token-stream scanner (no full parser, no cross-file data flow). Other languages, such as Java, are reported as not evaluated, never as clean.
  • AI explanations are optional and advisory. They can't change severity, state or score.

Next steps (if we had another week…)

  • Calibrate the weights on real, labelled repositories.
  • A real JS/TS parser and cross-file taint tracking.
  • Docker sandbox on by default (the only real isolation boundary).
  • Independent second-reviewer labels on real repositories.
