# Putting the dashboard online (Vercel page + Render API)

```
browser ──► Vercel (static page, strict CSP) ──/v1/* rewrite──► Render (FastAPI + embedded worker, SQLite)
```

The page is the same `web/` the API serves locally. On load it calls `GET /v1/public/status` and picks a mode:
**live/demo** (API answers), or **static** (no API: inert UI with an explanation). So the Vercel site never breaks if the
API is asleep or gone.

## What the public gets, and what it deliberately does not
* **Read-only demo login** (`demo@avishkar.dev`, published on the page on purpose; role `viewer`). It browses pre-scanned
  sample projects: the real pipeline run on the files in `sample_projects/` at startup, including the before/after fix,
  and the Go sample correctly shown as *not evaluated*. A viewer cannot upload, triage, explain, or see users/keys/audit.
* **Uploads are admin-only** (`AVISHKAR_UPLOADS=admin`). Render has no Docker daemon, so the worker runs as a plain child
  process, which is *not* an isolation boundary. The public instance therefore never scans code from strangers.
  Only you (the admin account you create) can upload, and should only upload code you trust.
* The free plan **sleeps when idle** (first request ~30-60 s; the page says so) and its disk is **ephemeral**: the database
  is rebuilt and samples re-scanned on every start. Admin uploads do not survive a restart. For persistence use a
  PostgreSQL database and set `DATABASE_URL` (the code supports it; the Postgres CI job exercises it).

## One-time setup (you do this in the browsers)
1. **Render**: https://dashboard.render.com -> New -> **Blueprint** -> connect GitHub -> pick `Dev57668/avishkar`.
   Render reads `render.yaml`. When prompted, set `AVISHKAR_ADMIN_EMAIL` and `AVISHKAR_ADMIN_PASSWORD` (your private admin;
   use a long unique password). Apply. First build takes a few minutes.
2. Open `https://<your-service>.onrender.com/v1/public/status`; you should see `"demo": true`. The service URL is shown in
   the Render dashboard (the blueprint asks for the name `avishkar-api`, so it is usually `https://avishkar-api.onrender.com`).
3. **Vercel**: in `vercel.json` add the rewrite (replace the host with your real service URL), commit and push:

   ```json
   "rewrites": [
     { "source": "/v1/:path*", "destination": "https://avishkar-api.onrender.com/v1/:path*" }
   ]
   ```
   The browser then talks only to the Vercel origin, so the CSP stays `connect-src 'self'` and no CORS setup is needed.

## Operating notes
* Change the demo password: edit `AVISHKAR_DEMO_PASSWORD` in the Render dashboard (it is public by design, so never reuse it).
* Stop publishing it: set `AVISHKAR_PUBLISH_DEMO_LOGIN=0`; visitors then need credentials from you.
* Turn the instance fully read-only for everyone: `AVISHKAR_UPLOADS=off`.
* Session tokens are signed with `AVISHKAR_SECRET_KEY` (generated by Render). Rotating it signs everyone out.
* Login lockout (5 failures / 15 min per email) is stored in the database, so it resets when the free instance restarts.
* The Docker image used here is `infra/Dockerfile.api`; CI job `api-image` builds it and checks demo seeding and the
  upload policy on every push.

## Not solved here
* No TLS/WAF/rate limiting beyond what Render and Vercel provide; a determined visitor can hammer the public login.
* The shared demo password means audit logs cannot tell demo visitors apart.
* Real isolation for scanning arbitrary uploads needs a host that can run containers per scan (the `docker` sandbox mode).
